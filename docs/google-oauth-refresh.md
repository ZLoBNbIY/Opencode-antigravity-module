# Фоновое обновление Google OAuth в Hub

Hub раз в 5 минут проверяет включённые аккаунты в штатном generation store.
Он обновляет только ещё действующий access token, если до истечения осталось
не более 30 минут. Аккаунты без известного срока, с уже истёкшим токеном, с
требованием верификации или отключённым аккаунтом остаются на штатном пути
OpenCode по требованию. Кандидаты обрабатываются по сроку истечения, между
запусками OAuth CLI выдерживается 12–16 секунд. Выход из Hub отменяет ожидание
и не запускает следующие запросы.

В фоновой команде `refresh-due` используется атомарное обновление через
generation repository. Под блокировкой ещё раз сверяются строка, эпоха
и срок токена; если запись уже обновилась, нового обмена нет. Hub получает
только идентификаторы, сроки и статусы. Токены остаются в штатном хранилище,
без дополнительного хранения или логирования в Hub. `invalid_grant`
приостанавливает попытки для этой эпохи до повторного входа или смены
поколения; `429` останавливает весь проход на `Retry-After` (минимум 5 минут,
а без действительного заголовка — 15). Состояние пауз локально процессу Hub.

Отключение: `"google_proactive_refresh": false` в JSON-настройках Hub или
`AI_HUB_GOOGLE_PROACTIVE_REFRESH=0` до запуска Hub. Эти настройки не отключают
встроенную очередь самого плагина.

## Поддерживаемые версии

- **3.0.0:** Hub использует свой vendored CLI и указатель schema 1. Исходный
  `src/cli.ts` в репозитории отсутствует, поэтому расширение находится
  в собранном `plugin/dist/cli.js`. CLI 3.0.0 не открывает schema 2.
- **3.1.13:** Hub использует штатный репозиторий именно этой версии через
  изолированный процесс Node.js (20.6+). Loader проверяет SHA‑256 единственного
  подходящего `cli.js` из `~/.cache/opencode/npm` и открывает его функции только
  в памяти, не меняя пакет или pin. Штатный код 3.1.13 проверяет активное
  поколение и разрешает `relocatedTo` (schema 2). Обновляются только аккаунты
  с полномочиями `local`; режимы `vault` и `host` не обслуживаются. Во время
  записи используется штатный heartbeat, чтобы не запускать OAuth без
  регистрации процесса в механизме защиты от параллельного переноса.

При несовпадающем digest, другом pin, отсутствующих зависимостях, конфликте
pin или неоднозначном npm layout Hub пропускает обновление, не подставляя
старый writer. Hub не запускает перенос или миграцию. Проверка на временной
копии точного пакета и schema‑2 хранилища доступна через
`node --test tests/google-proactive-3113.test.mjs` (при необходимости укажите
путь к копируемому `node_modules` в `HUB_TEST_3113_NODE_MODULES`).

## Почему убран старый периодический запрос квот

Старый worker вызывал `quota --refresh --json` и выбрасывал результат.
Standalone CLI в 3.0.0 и 3.1.13 формирует `updatedAccount` в памяти,
но не записывает его или возвращённые квоты в generation store: результат
идёт только в JSON CLI. Hub показывает квоты из generation store, а не
из stdout этой команды. Поэтому периодический вызов не обновлял мониторинг
Hub, зато мог инициировать OAuth-обмен и запросы квот для всего пула.
Ручное обновление квот, проверка после добавления аккаунта и health-check
не изменены.
