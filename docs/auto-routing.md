# Auto: выбор маршрута по результатам проверки

Режим Auto (`provider_routes.<provider> = "auto"`, старый alias `"default"`)
сравнивает настроенные VLESS, DNS Hub и внешний HTTP(S)-прокси отдельно для
каждого провайдера. Ручные маршруты остаются фиксированными. В интерфейсе
кнопка Auto сохраняет значение `"auto"`; файлы с `"default"` продолжают
работать как раньше.

- VLESS участвует, если он включён и сохранена строка подключения.
- DNS Hub использует выбранный режим DNS: обычный DNS, DoH или DoT.
- HTTP(S)-прокси участвует, если сохранён его внешний адрес.
- Прямое подключение исключено из Auto.

Проверки выполняются параллельно: соединение через выбранный транспорт,
проверка TLS-сертификата и запрос GET к служебному адресу без API-ключей,
cookie, пользовательских запросов и генерации. HTTP 401, 404, 405 и 429
допускаются как ответы доступного сервиса; HTTP 403 и ошибки шлюза не проходят
проверку. Такая проверка оценивает транспорт, а не доступ аккаунта к модели.
Поэтому `429` в проверке Auto означает только «сервер ответил». Ограничения
аккаунта оцениваются отдельно, по ответам на реальные запросы генерации;
они не должны понижать оценку VLESS, DNS или HTTP-прокси.

Сначала сравнивается число доступных основных доменов, затем медианная
задержка HTTPS. Результаты сохраняются в памяти на минуту. При изменении
настроек результаты прежней конфигурации больше не используются.
Проверка продолжается в маршрутизаторе, даже если интерфейс не опрашивает его.

Если выбранный транспорт не открывает новое соединение, Auto пробует
следующий маршрут, успешно прошедший проверку. Домены, для которых проверка
HTTPS на конкретном маршруте уже завершилась ошибкой, через него не идут.
После открытия соединения поток и тело запроса не переотправляются:
оборвавшаяся генерация автоматически не повторяется.

Если настроенных или доступных маршрутов нет, запрос завершается ошибкой;
скрытого перехода на прямое подключение нет. Повторные проверки недоступных
маршрутов выполняются через 10 секунд.

В карточке провайдера кнопка Auto показывает измеренный выбор. В разделе
«Сравнение маршрутов Auto» видны доступность и задержка каждого кандидата.
Кнопка «Сравнить маршруты» запускает проверку без изменения ручного маршрута.

## OpenCode и провайдеры вне Hub

AI HUB не назначает OpenCode общий HTTP-прокси. Встроенные модели OpenCode
(`opencode/*`), каталог и провайдеры, не настроенные в Hub, используют обычную
сеть OpenCode. Системный VPN, прозрачная маршрутизация роутера и прокси,
которые пользователь настроил отдельно от Hub, не меняются.

Для управляемых API Hub устанавливает локальный плагин OpenCode V2. Плагин
перенаправляет только запросы моделей с известными ID провайдеров и
согласованными адресами API; остальные запросы не проходят через диспетчер.
При маршруте «Напрямую» он не переписывает запрос. Для маршрутизации
генерации ChatGPT через Hub используется HTTP вместо WebSocket. Служебное
обновление OAuth-токена самим OpenCode не обрабатывается этим плагином.
При переключении ChatGPT с «Напрямую» на маршрут Hub перезапустите OpenCode,
чтобы заново выбрался транспорт.
Для Google Antigravity используйте патч транспорта Hub, а для TokenLavka —
настроенный Hub локальный endpoint.

### Google: пауза после ошибок квоты и OAuth

Три ответа `429` либо `409` с подтверждённой ошибкой квоты за 60 секунд
ставят выбранную пару «аккаунт / модель» на паузу на 15 минут. Если Google
передал `Retry-After` или время сброса, Hub соблюдает этот срок уже после
первого такого ответа и не укорачивает его. Успешный HTTP-ответ сбрасывает
счётчик ошибок, но не отменяет уже действующую паузу. Этот механизм не
меняет показания квоты и не выбирает другой аккаунт. Состояние паузы
хранится в памяти плагина.

Проверка срока OAuth-токена работает отдельно от маршрутизации генерации.
Условия, версии плагина и способ отключения описаны в
[руководстве по фоновому OAuth-обновлению](google-oauth-refresh.md).

Если OpenCode был запущен предыдущей версией Hub с общим прокси, после
обновления перезапустите **и Hub, и OpenCode** кнопками Hub: старый фоновый
сервер OpenCode сохраняет окружение, с которым был запущен.

Кнопка «Перезапустить OpenCode» закрывает **все** окна Desktop (в том числе
запущенные пользователем или предыдущей версией Hub), ждёт их реального выхода,
перезапускает фоновый сервер через `opencode service restart` и открывает новое
окно. Без закрытия окна старый плагин остаётся загруженным, и перезапуск
выглядит как неработающий.
