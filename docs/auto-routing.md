# Auto: выбор маршрута по результатам проверки

Режим Auto (`provider_routes.<provider> = "default"` или `"auto"`) сравнивает
настроенные VLESS, DNS Hub и внешний HTTP(S)-прокси отдельно для каждого
провайдера. Ручные маршруты остаются фиксированными.

- VLESS участвует, если он включён и сохранена строка подключения.
- DNS Hub использует выбранный режим DNS: обычный DNS, DoH или DoT.
- HTTP(S)-прокси участвует, если сохранён его внешний адрес.
- Прямое подключение и экспериментальный Google SmartDNS исключены из Auto.

Проверки выполняются параллельно: соединение через выбранный транспорт,
проверка TLS-сертификата и запрос GET к служебному адресу без API-ключей,
cookie, пользовательских запросов и генерации. HTTP 401, 404, 405 и 429
допускаются как ответы доступного сервиса; HTTP 403 и ошибки шлюза не проходят
проверку. Такая проверка оценивает транспорт, а не доступ аккаунта к модели.

Сначала сравнивается число доступных основных доменов, затем медианная
задержка HTTPS. Результаты сохраняются в памяти на минуту. При изменении
настроек результаты прежней конфигурации больше не используются.
Проверка продолжается в маршрутизаторе, даже если интерфейс не опрашивает его.

Если выбранный транспорт не открывает новое соединение, Auto пробует
следующий маршрут, успешно прошедший проверку. Домены, для которых проверка
HTTPS на конкретном маршруте уже завершилась ошибкой, через него не идут.
После открытия соединения поток и тело запроса не переотправляются:
оборвавшаяся генерация автоматически не повторяется.

Если настроенных или доступных маршрутов нет, запрос завершается ошибкой;
скрытого перехода на прямое подключение нет. Повторные проверки недоступных
маршрутов выполняются через 10 секунд.

В карточке провайдера кнопка Auto показывает измеренный выбор. В разделе
«Сравнение маршрутов Auto» видны доступность и задержка каждого кандидата.
Кнопка «Сравнить маршруты» запускает проверку без изменения ручного маршрута.
