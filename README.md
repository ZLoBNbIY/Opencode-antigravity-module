# OpenCode Antigravity Module (Ветка V2)

> [!IMPORTANT]
> **Ветка `V2` разработана специально для OpenCode версии 2.0.27 и выше.**  
> Данная ветка включает полную поддержку архитектуры OpenCode 2.x:
> * Внутренняя база данных SQLite (`opencode.db`) и таблица `credential`.
> * Мгновенная синхронизация учетных записей через интерфейс `opencode-cli auth import / export`.
> * Поддержка двойного пути конфигурации `auth.json` (`%USERPROFILE%\.opencode\auth.json` и `%USERPROFILE%\.local\share\opencode\auth.json`).
> * Мульти-аккаунт и авто-ротация Google Antigravity & OpenAI ChatGPT.
> * Устранение несовместимости JSON Schema (`exclusiveMinimum`) с Protobuf-валидатором Gemini API.
> * Автоматическая очистка блокировок `service.json*` для предотвращения ошибок Windows Desktop IPC.
> 
> *Для устаревших версий OpenCode 1.x (до 2.0.0) используйте ветку `main`.*

> **Комплексный модуль интеграции Google Antigravity OAuth для OpenCode**  
> Доступ к моделям **Gemini 3.8 Flash**, **Gemini 3.7 Flash / Pro** и **Claude** через аккаунты Google с поддержкой мульти-аккаунта, умной ротации квот, нативного GUI-менеджера и полным устранением зависаний стриминга («Размышление...»).

## ✨ Возможности модуля

* 🚀 **Прямой доступ к моделям Gemini 3.8 / 3.7**: Используйте новейшие флагманские модели Google без необходимости оформлять платные API-ключи Google Cloud.
* 🔄 **Мульти-аккаунт и автоматическая ротация Google**: Подключайте неограниченное количество Google аккаунтов без взаимного затирания. При исчерпании квоты на одном аккаунте плагин автоматически переключается на следующий.
* 🤖 **Поддержка аккаунтов и квот ChatGPT / OpenAI**: Подключение учетных записей ChatGPT (Plus/Pro/Team/Edu) через OAuth в браузере с отображением живых квот (основное окно 3-5 часов и недельный лимит 7 дней) и переключением активного аккаунта для OpenCode в 1 клик.
* 🧠 **Полная поддержка цепочки рассуждений (Thinking/Reasoning)**: Корректный парсинг и отображение мыслей модели (`thoughtSignature`) в реальном времени.
* 🖥️ **Нативный Desktop GUI Менеджер (Antigravity Hub)**: Удобное графическое приложение на Python (CustomTkinter) с фирменной иконкой для мониторинга остатка квот Google и OpenAI, смены стратегий, просмотра логов и авторизации.
* 📦 **Автоустановка Node.js**: Скрипт установки `install.ps1` самостоятельно находит или тихо устанавливает Node.js LTS, если он отсутствует на компьютере.
* 🛠️ **Автономный CLI инструмент**: Управление сессиями и квотами прямо из терминала.

## 🛠️ Устранённые проблемы и баги оригинального плагина

В базовой сборке `@cortexkit/opencode-antigravity-auth` присутствовал ряд критических дефектов, которые полностью исправлены в этом репозитории:

### 1. Зависание на статусе «Размышление...» (Thinking Hang)
* **Причина**: Внутренний движок `@ai-sdk/google` в OpenCode ожидает стрим в формате Server-Sent Events (SSE) с кандидатами на верхнем уровне JSON (`candidates: [...]`). Оригинальный плагин ожидал вложенную структуру (`response: { candidates: [...] }`), из-за чего сбрасывал чанки.
* **Решение**: Функция `transformSseLineWithMetadata` переписана так, чтобы прозрачно поддерживать оба формата ответа Google API.

### 2. Ложная блокировка мягкой квоты (HTTP 412 FAILED_PRECONDITION)
* **Причина**: В плагине по умолчанию было включено правило `"soft_quota_threshold_percent": 20`. Как только пользователь расходовал хотя бы 20% лимита, плагин принудительно возвращал HTTP 412, блокируя диалог задолго до исчерпания реальных лимитов Google.
* **Решение**: Порог мягкой защиты выставлен на `100` (полное отключение блокировки до исчерпания 100% квоты) с автоматическим переключением на запасные аккаунты.

### 3. Зависание CLI в неинтерактивных терминалах
* **Причина**: Функция `isCliAuthorize` блокировала процесс в ожидании TTY stdin, из-за чего скрипты автоматизации и фоновые вызовы зависали навсегда.
* **Решение**: Добавлена проверка `process.stdin.isTTY` и корректное делегирование авторизации.

### 4. Ошибки отмены потока (WebStreams TransformStream)
* **Причина**: При нажатии кнопки «Стоп» в UI OpenCode вызывался метод `.cancel()` стрима, вызывавший необработанные исключения и повреждавший состояние сессии.
* **Решение**: Добавлены безопасные блоки обработки сигналов прерывания стрима.

### 5. Стирание существующих Google аккаунтов при добавлении нового (Multi-Account Overwrite Bug)
* **Причина**: В оригинальном плагине при каждом вызове CLI команды `login` был жестко зашит флаг `replaceAll = true` (`request.startFresh && request.accounts.length === 0`). При успешной авторизации функция `persistAccountPool` очищала весь файл `antigravity-accounts.json`, стирая ранее добавленные аккаунты и оставляя только один последний.
* **Решение**: Вызов `persistAccountPool` переведен в режим безопасного слияния (`replaceAll = false`). Теперь при добавлении второго и последующих Google аккаунтов они корректно сохраняются в общем пуле, а повторный вход обновляет токены без потери данных.

### 6. Ошибка `[WinError 2] Не удается найти указанный файл` в Antigravity Hub
* **Причина**: При отсутствии глобального Node.js в `PATH` вызов внешней утилиты авторизации падал с системной ошибкой Windows `ERROR_FILE_NOT_FOUND`.
* **Решение**: Добавлен интеллектуальный поиск `node.exe` (включая рантаймы в Cursor, DeepSeek и др.), автоустановка Node.js в `install.ps1`, а также понятные информативные уведомления в интерфейсе.

### 7. Сбой миграции на Windows и блокировка запросов (`EPERM: operation not permitted, fsync` / HTTP 412)
* **Причина**: Начиная с версии плагина 3.0.0, используется новая поколенческая архитектура хранения аккаунтов (`*.generation`). При попытке синхронизации дескрипторов каталогов файловая система Windows (NTFS) возвращает системную ошибку `EPERM`, из-за чего плагин не мог мигрировать пул аккаунтов и блокировал любые запросы кодом `412 FAILED_PRECONDITION` («Antigravity accounts require offline migration»).
* **Решение**: Внедрён асинхронный Win32-полифилл для `FileHandle.sync`, безопасно подавляющий специфичные ошибки Windows, а скрипт `patch_plugin.mjs` теперь автоматически находит кэшированные пакеты OpenCode и выполняет миграцию хранилища.

### 8. Ошибка «Недостаточно средств» из-за провайдера OpenCode Zen
* **Причина**: OpenCode по умолчанию направлял новые запросы во встроенный платный шлюз `opencode/gemini-3.8-flash` (OpenCode Zen), требующий подписки или средств на балансе.
* **Решение**: В шаблоны и установщик добавлена директива по умолчанию `"model": "google/antigravity-gemini-3.8-flash"`. Теперь OpenCode сразу работает через бесплатные Google OAuth токены.

### 9. Сбой запуска OpenCode и неверный статус в Antigravity Hub
* **Причина**: В последних версиях OpenCode для Windows устанавливается в каталог `@opencodedesktop` (вместо `@opencode-aidesktop`), запуск с флагом скрытого окна подавлял Electron UI, а статус процесса отслеживал только одно имя исполняемого файла, игнорируя фоновый CLI-сервер `opencode-cli.exe`.
* **Решение**: Менеджер переведен на поиск всех актуальных каталогов, нативный запуск Windows Shell `os.startfile(exe)` и мульти-процессный мониторинг (`OpenCode.exe` + `opencode-cli.exe`).

### 10. Ошибка 400 Bad Request: `Unknown name "exclusiveMinimum"` при вызове инструментов OpenCode
* **Причина**: OpenCode генерирует схемы параметров инструментов (`glob`, `grep`, `webfetch` и др.) по современному стандарту JSON Schema с полями `exclusiveMinimum` и `exclusiveMaximum`. Внутренний Protobuf-валидатор Google Gemini API не поддерживает `exclusiveMinimum` и отклоняет вызовы с HTTP 400: `Invalid JSON payload received. Unknown name "exclusiveMinimum" at 'request.tools[0].function_declarations...': Cannot find field.`.
* **Решение**: Функция `toGeminiSchema` и список `UNSUPPORTED_SCHEMA_FIELDS` расширены: `exclusiveMinimum` для целочисленных типов (`INTEGER`) прозрачно трансформируется в эквивалентное `minimum: value + 1`, числовые ограничения сохраняются в подсказках описания (`description`), а несовместимые с Google API мета-поля полностью фильтруются перед отправкой.

### 11. Ошибка Desktop IPC / `EPERM: FileSystem.rename service.json` и конфликт версий OpenCode 1.x / 2.x
* **Причина**: На Windows при перезапуске процессов OpenCode в `%USERPROFILE%\.local\state\opencode\` оставались заблокированные файлы `service.json` и временные `.tmp`. Фоновый сервер Bun падал с системной ошибкой: `Desktop IPC handler failed: PlatformError: FileSystem.rename ... EPERM: operation not permitted`. Кроме того, при несовместимости установленных версий (1.19.0 против 2.0.27) база данных `opencode.db` с таблицей `session_v2` приводила к сбою устаревшего клиента: `Error: Database is not empty and has no session table`.
* **Решение**: Antigravity Hub теперь автоматически очищает остаточные файлы блокировок и `service.json*` перед запуском/перезапуском OpenCode, опрос процессов переведен на мгновенный `tasklist /fi`, а ярлыки OpenCode на Рабочем столе автоматически перенаправляются на актуальный исполняемый файл 2.0.27.

### 12. Ошибка 400 `invalid_request: Required parameter is missing: response_type` при авторизации Google
* **Причина**: В функции открытия браузера `openBrowserDefault` для Windows использовалась команда `cmd /c start "" url`. В командной строке Windows символ `&` является разделителем команд. При открытии ссылки авторизации Google OAuth `cmd.exe` обрезал ссылку на первом же параметре (`&response_type=code`), из-за чего браузер получал урезанный адрес без обязательных параметров авторизации.
* **Решение**: Вызов браузера переведен на вызов PowerShell `Start-Process` с Base64-кодированием (`-EncodedCommand`). Это гарантирует передачу URL со всеми параметрами в исходном виде в браузер по умолчанию пользователя без вмешательства командного процессора `cmd.exe`.

### 13. Синхронизация аккаунтов OpenAI / ChatGPT с базой данных OpenCode 2.0 (`opencode.db`)
* **Причина**: В версиях OpenCode 2.0.x (включая 2.0.27+) данные интеграций хранятся не только в `auth.json`, но и во внутренней SQLite базе данных (`%USERPROFILE%\.local\share\opencode\opencode.db`) в таблице `credential`. При добавлении аккаунта ChatGPT только в файл `auth.json` запущенный демон OpenCode 2.0 не отображал модели в интерфейсе.
* **Решение**: Модуль `openai_manager.py` в ветке `V2` автоматически выполняет тройную синхронизацию: пишет в оба пути `auth.json`, напрямую обновляет SQLite таблицу `credential` и вызывает команду `opencode-cli auth import`. Модели ChatGPT становятся доступны в интерфейсе сразу без перезапуска.

## 🔑 Авторизация Google аккаунтов

Для работы модуля требуется хотя бы один авторизованный аккаунт Google.

### Вариант А: Через консоль (CLI)

Запустите команду входа:
```bash
node plugin/dist/cli.js login
```
В терминале откроется ссылка или запустится браузер:
1. Войдите в свой Google аккаунт.
2. Подтвердите разрешения для Antigravity.
3. Токены автоматически сохранятся в защищённом хранилище:
   * **Windows**: `%USERPROFILE%\.local\share\opencode\auth.json`

Чтобы добавить **второй и последующие аккаунты** для ротации, просто повторите команду `login` в другом профиле браузера.

1. Запустите `gui-manager/start_manager.bat`.
2. Перейдите на вкладку **«Управление»** -> нажмите **«Войти в новый аккаунт Google»**.

## ⚙️ Конфигурация OpenCode

Чтобы OpenCode использовал модуль и модели Google Antigravity, убедитесь, что в файле конфигурации OpenCode указан плагин.

Файл конфигурации:
* **Windows**: `%USERPROFILE%\.config\opencode\opencode.json`
* **Linux/macOS**: `~/.config/opencode/opencode.json`

Содержимое `opencode.json`:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "google/antigravity-gemini-3.8-flash",
  "plugin": [
    "@cortexkit/opencode-antigravity-auth@latest"
  ],
  "provider": {
    "google": {
      "options": {
        "apiKey": "antigravity"
      }
    }
  }
}
```

> **Как избежать ошибки «Недостаточно средств»:**  
> Не выбирайте модели провайдера OpenCode Zen (`opencode/...`), так как они требуют платных кредитов платформы OpenCode. Всегда используйте модели из списка выше с префиксом `google / antigravity-...`.

## 🎛️ Параметры `antigravity.json`

Файл тонкой настройки модуля расположен по адресу:
* **Windows**: `%USERPROFILE%\.config\opencode\antigravity.json`
* **Linux/macOS**: `~/.config/opencode/antigravity.json`

### Рекомендуемая конфигурация:
```json
{
  "$schema": "https://raw.githubusercontent.com/cortexkit/opencode-antigravity-auth/main/schema.json",
  "account_selection_strategy": "hybrid",
  "soft_quota_threshold_percent": 100,
  "switch_on_first_rate_limit": true,
  "quota_style_fallback": true,
  "debug": false
}
```

### Подробное описание настроек:

| Параметр | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `account_selection_strategy` | `string` | `"hybrid"` | Стратегия выбора аккаунта из пула:<br>• `"hybrid"`: комбинация наименьшей нагрузки и максимального остатка квоты.<br>• `"round-robin"`: поочерёдный перебор аккаунтов.<br>• `"least-used"`: выбор аккаунта с минимальным расходом квоты. |
| `soft_quota_threshold_percent` | `number` | `100` | **Критический параметр!** Процент расхода квоты, при котором аккаунт считается исчерпанным.<br>**Важно:** Значение `100` отключает ложные блокировки 412 и использует аккаунт на полную мощность. |
| `switch_on_first_rate_limit` | `boolean` | `true` | Немедленно переключаться на следующий аккаунт при получении ошибки 429 (лимит запросов в минуту), не дожидаясь тайм-аута. |
| `quota_style_fallback` | `boolean` | `true` | Разрешает переключение стилей заголовков авторизации при исчерпании квот основного API. |
| `debug` | `boolean` | `false` | Включает подробное логирование запросов, заголовков и ротации в папку логов. |

### Запуск GUI:

### Возможности интерфейса:
1. **Вкладка «Аккаунты и квоты»**:
   * **Переключатель провайдеров**: удобный переключатель между **Google (Antigravity)** и **OpenAI (ChatGPT)**.
   * **Google (Antigravity)**:
     * **Раздельные шкалы лимитов (5h и Недельный)**: точное отображение 5-часового (5h) и недельного (Weekly) окон квот для каждого семейства моделей (Gemini Flash/Pro 2.5/3.7/3.8 и Claude / другие) с индивидуальными таймерами сброса.

     * Добавление новых Google-аккаунтов в ротацию по кнопке `+ Добавить аккаунт Google`.
   * **OpenAI (ChatGPT)**:
     * Автоматический импорт существующей сессии из OpenCode при первом запуске.
     * Авторизация новых ChatGPT-аккаунтов через браузер по кнопке `+ Добавить аккаунт OpenAI` (OAuth PKCE).
     * Отображение живых квот прямо из API ChatGPT: **Основное окно (3-5 часов)** и **Недельный лимит (7 дней)** с точным таймером сброса.
     * Статус тарифного плана (`PLUS`, `PRO`, `TEAM`, `K12`, `FREE`).
     * Переключение активного аккаунта для OpenCode в один клик (`⭐ Использовать в OpenCode`).
     * Удаление неиспользуемых аккаунтов (`🗑`).
   * 📤 **Экспорт и 📥 Импорт аккаунтов (Перенос между ПК)**:
     * Кнопка **«📤 Экспорт»**: сохраняет единый резервный JSON-файл со всеми Google- и ChatGPT-аккаунтами, токенами и настройками.
     * Кнопка **«📥 Импорт»**: быстро восстанавливает или переносит аккаунты на другой ПК с автоматической регистрацией в OpenCode 2.0+ (Generation Store + SQLite).
   * ⏱️ **Автообновление каждые 10 минут**: Фоновый опрос квот Google и OpenAI с обратным отсчетом в строке состояния (`⏱ Автообновление квот: через 09:59`).
2. **Вкладка «Настройки автопереключения»**:
   * Интерактивное переключение стратегий ротации Google аккаунтов (`hybrid`, `sticky`, `round-robin`).
   * Ползунок порога мягкой защиты квоты (`soft_quota_threshold_percent`).
   * Управление фоновым автообновлением квот.
3. **Вкладка «OpenCode & Диагностика»**:
   * Перезапуск, остановка и запуск десктопного приложения OpenCode в один клик.
   * Быстрый доступ к папке конфигов (`~/.config/opencode`) и логов.

## ❓ Решение проблем (Troubleshooting)

### Q: OpenCode снова завис на «Размышление...»
1. Проверьте параметр `soft_quota_threshold_percent` в `~/.config/opencode/antigravity.json`. Он должен быть равен `100`.
2. Запустите `node scripts/patch_plugin.mjs`, чтобы убедиться, что патчи стриминга применены.
3. Если старый диалог остался зависшим в базе данных, создайте новый диалог (кнопка `+ New Session` в OpenCode).

### Q: Ошибка `412 FAILED_PRECONDITION`
Эта ошибка означает, что все аккаунты исчерпали квоту защиты. Убедитесь, что в `antigravity.json` установлено `"soft_quota_threshold_percent": 100`, либо добавьте ещё один аккаунт Google через `node plugin/dist/cli.js login`.

### Q: Ошибка «Недостаточно средств» (Insufficient account funds / QuotaExceeded)
* **Причина**: В выпадающем списке моделей OpenCode по умолчанию выбран встроенный облачный провайдер **OpenCode Zen** (`opencode/gemini-3.8-flash`), расходующий платный баланс подписки OpenCode, а не бесплатные OAuth-аккаунты Antigravity.
* **Решение**:
  1. В левом нижнем углу диалога OpenCode выберите провайдера **Google** и модель:
     * `google / antigravity-gemini-3.8-flash`
     * `google / antigravity-claude-sonnet-4-6-thinking`
  2. В файле `%USERPROFILE%\.config\opencode\opencode.json` установлена настройка по умолчанию:
     `"model": "google/antigravity-gemini-3.8-flash"` — теперь все новые диалоги сразу используют Antigravity.

### Q: Antigravity Hub не видит статус OpenCode или не может его запустить
* **Причина**: На некоторых версиях Windows приложение OpenCode Desktop устанавливается в каталог `@opencodedesktop`, а системные процессы регистрируются как `opencode-cli.exe` и `OpenCode.exe`.
* **Решение**: В последнем обновлении менеджера пути поиска расширены (поддерживаются `@opencodedesktop`, `@opencode-desktop`, `@opencode-aidesktop`), запуск выполняется через нативную системную оболочку `os.startfile`, а статус отслеживает как UI, так и фоновый CLI-сервис.

### Q: Ошибка 412 «Antigravity accounts require offline migration»
* **Причина**: Начиная с версии 3.0.0, плагин Antigravity перешел на поколенческую систему хранения аккаунтов (`*.generation`), требующую миграции файла `antigravity-accounts.json` и патча Windows `fsync`.
* **Решение**: Просто запустите `node scripts/patch_plugin.mjs`. Скрипт автоматически найдет все установленные версии плагина в `%USERPROFILE%\.cache\opencode\npm`, наложит Windows-полифилл и выполнит безопасную миграцию хранилища.

### Q: Ошибка `Desktop IPC handler failed: EPERM: operation not permitted, rename service.json.tmp`
* **Причина**: Фоновый процесс `opencode-cli.exe` был завершен аварийно или удерживал дескриптор файла `service.json` в `%USERPROFILE%\.local\state\opencode\`.
* **Решение**:
  1. Нажмите «Остановить OpenCode» или «Перезапустить OpenCode» в Antigravity Hub — менеджер снимет зависшие процессы и автоматически удалит временные блокировки.
  2. Либо вручную в PowerShell:
     ```powershell
     Stop-Process -Name "OpenCode","opencode-cli" -Force -ErrorAction SilentlyContinue
     Remove-Item "$env:USERPROFILE\.local\state\opencode\service.json*" -Force -ErrorAction SilentlyContinue
     ```

### Q: Ошибка `Error: Database is not empty and has no session table` (Версия: 1.19.0)
* **Причина**: Запущена старая версия OpenCode 1.x (например, через старый ярлык), в то время как база данных `opencode.db` уже мигрирована на схему OpenCode 2.x (`session_v2`).
* **Решение**: Убедитесь, что ярлыки на Рабочем столе ссылаются на актуальный OpenCode 2.0.27. В последней версии репозитория ярлыки перенаправляются автоматически.

### Q: Ошибка `Required parameter is missing: response_type` при добавлении Google аккаунта в браузере
* **Причина**: На Windows командная строка `cmd.exe` обрезала длинный OAuth URL по первому символу `&`. В браузере открывался неполный адрес без параметров авторизации.
* **Решение**: Запустите `node scripts/patch_plugin.mjs`. Скрипт заменит открытие ссылок через `cmd` на вызов PowerShell `Start-Process`, сохраняющий все параметры запроса в неизменном виде.
